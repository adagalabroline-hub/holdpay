HOLDPAY PROJECT - FILE-BY-FILE NOTES
====================================

Purpose
-------
This document explains the purpose of every project file tracked in Git at the
time this guide was created. Paths are relative to the repository root.
Generated build output, caches, IDE state, and local machine configuration are
not included in the tracked-file inventory.

Project overview
----------------
HoldPay is a Kenya-focused local-commerce concept with a browser prototype,
Flutter Android/iOS starter, and an Odoo 18 backend addon. The website and app
are prototypes; the backend payment status is intentionally not connected to a
payment provider. This project does not hold or transfer real funds.

ROOT: WEB PROTOTYPE AND PROJECT DOCUMENTATION
---------------------------------------------

.gitignore
  Excludes local secrets, editor/OS files, Flutter and Dart caches/build
  output, Android local.properties, and generated iOS Flutter configuration.

index.html
  Entry page for the browser prototype. Loads the brand, navigation, app
  container, footer, dialog, stylesheet, and app.js.

styles.css
  Website layout, typography, colors, component styling, forms, cards,
  marketplace/dashboard presentation, and responsive breakpoints.

app.js
  Client-side browser prototype behavior: sample marketplace and role
  dashboards, browser-local demo data, signup/sign-in dialogs, listings,
  simulated orders/milestones, buyer-proposed service contracts, written work
  scope, seller acceptance, stage submission, buyer approval choices, reviews,
  and concern walkthrough interactions. It is not connected to the Odoo
  backend.

holdpay-logo.svg
  Reusable vector logo displayed by the browser prototype.

BACKEND-API.md
  Documents the Odoo JSON-RPC API, session authentication approach, request
  examples, role and KYC gates, current payment limitations, and unimplemented
  production integrations. Also documents the proposed Nairobi-to-Kakamega
  parcel flow for an unregistered recipient using SMS instructions and
  pickup-code verification through an agent's future USSD provider.

ODOO-DEPLOYMENT.md
  Odoo 18 hosting and installation guidance, addon scope, production decisions,
  and the proposed HoldPay-for-Odoo extension, including future parcel and
  SMS/USSD provider requirements.

PARTNERSHIP-NOTES.md
  Product and partnership concept notes, pilot discussion, and prototype
  limitations for prospective payment and commerce partners, including the
  proposed parcel-to-unregistered-recipient use case and its SMS/USSD needs.

ODOO 18 ADDON: holdpay_odoo/
----------------------------

holdpay_odoo/__init__.py
  Loads the addon's controllers and Odoo model extensions.

holdpay_odoo/__manifest__.py
  Odoo module metadata, dependencies, install data files, and frontend CSS
  asset registration.

holdpay_odoo/controllers/__init__.py
  Imports the addon website and API controller module.

holdpay_odoo/controllers/main.py
  Website onboarding routes and authenticated JSON-RPC API endpoints for
  account role, account status, listings, agents, orders, milestones, cases,
  and reviews. It enforces server-side role, verification, and ownership
  checks. Payment is not configured or processed.

holdpay_odoo/controllers/service_api.py
  Authenticated Odoo JSON-RPC endpoints for discovering verified seller
  service providers, proposing and accepting written service agreements,
  submitting and approving agreed work milestones, and recording concerns.
  Approval records do not collect or release money.

holdpay_odoo/data/holdpay_sequence.xml
  Defines the human-readable sequence used to assign references to HoldPay
  orders/deals.

holdpay_odoo/models/__init__.py
  Imports the partner extension and HoldPay marketplace models.

holdpay_odoo/models/res_partner.py
  Extends Odoo contacts with HoldPay account role, identity/KYC status, seller
  or agent business-verification status, and pickup-agent operating area.

holdpay_odoo/models/marketplace.py
  Defines Odoo records for seller listings, orders/deals, mediation cases, and
  buyer reviews, including server-side data constraints and order references.

holdpay_odoo/models/service_contract.py
  Defines service agreements and ordered milestones, including service
  category, buyer/provider, written scope, agreed price, client approval mode,
  concern status, and validation that milestone amounts equal the agreed total.

holdpay_odoo/security/ir.model.access.csv
  Grants portal users read-only model access and grants Odoo system
  administrators full model access. API writes are performed through
  controller checks.

holdpay_odoo/security/holdpay_rules.xml
  Record rules limiting portal reads to published/owned listings and deals,
  cases, and reviews involving the logged-in user.

holdpay_odoo/security/service_contract_access.csv
  Grants portal users read-only access to service agreements and milestones;
  grants Odoo system administrators full access.

holdpay_odoo/security/service_contract_rules.xml
  Limits portal reads of service agreements and milestones to their client or
  provider participants.

holdpay_odoo/static/src/css/holdpay.css
  Styles the HoldPay landing page, account onboarding, pending-verification,
  role-selection, and related Odoo website templates.

holdpay_odoo/views/partner_views.xml
  Adds HoldPay role and verification fields to the Odoo contact form for
  administrator review.

holdpay_odoo/views/marketplace_views.xml
  Defines administrator list/form views and the HoldPay menu for listings,
  orders/payment status records, and mediation cases.

holdpay_odoo/views/service_contract_views.xml
  Defines administrator list/form views and menu access for service
  agreements, their milestones, and recorded concerns.

holdpay_odoo/data/service_contract_sequence.xml
  Defines the human-readable reference sequence for service agreements.

holdpay_odoo/views/website_templates.xml
  Defines QWeb pages for the HoldPay landing page, role selection, pending
  mobile KYC, and verified account status.

Important project boundaries
----------------------------
- The browser marketplace uses local demo data; it is not connected to Odoo.
- The Flutter source demonstrates the user journey; it is not yet connected to
  the Odoo API and performs no real KYC.
- M-Pesa Till, Pochi la Biashara, M-Pesa Paybill, and GlobalPay are recorded as
  possible payment method names only. No provider API, settlement, custody,
  transfer, or refund is implemented.
- KYC status must only be approved by a trusted verification process. Website
  and mobile clients must not be trusted to set their own verified status.
- Installation and live API operation require an Odoo 18 staging or production
  server; static checks alone do not confirm runtime compatibility.
